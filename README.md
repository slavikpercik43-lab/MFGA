# Робот «Довезти кубик» (хакатон «Малые робототехнические платформы»)

Программа для мобильного робота на **ESP32 Dev Module** с четырьмя моторами
и меканум-колёсами (драйверы **L298N**). Робот сам, без ноутбука, едет по
заданному маршруту к манипулятору, запрашивает погрузку кубика по UDP, ждёт
подтверждения и после этого сам едет в зону финиша и останавливается.

Код: [`robot_route/robot_route.ino`](robot_route/robot_route.ino)

## Как загрузить программу

1. Установить **Arduino IDE** и в Менеджере плат добавить пакет **esp32 (Espressif), ядро 3.x**.
2. Открыть `robot_route/robot_route.ino`.
   Папка скетча должна называться так же, как файл (`robot_route`).
3. Инструменты → Плата → **ESP32 Dev Module**; выбрать COM-порт платы.
   Дополнительных библиотек не нужно: `WiFi` и `WiFiUdp` входят в ядро ESP32.
4. Перед боевым запуском проверить в начале файла:
   ```cpp
   const bool MOTOR_TEST_ONLY = false;
   const bool AUTO_START = true;
   ```
5. Нажать «Загрузить». Если загрузка не стартует (`Connecting...`), зажать на плате кнопку **BOOT**.
6. Поставить робота в зону старта **передом влево по карте** и включить питание
   моторов и платы. Через 5 секунд робот поедет сам.

Монитор порта (115200) нужен только для отладки: робот печатает шаги маршрута
и обмен с манипулятором (`TX:` / `RX:`).

## Подключение

| Мотор | IN1 | IN2 |
|---|---|---|
| 1 — передний левый (FL)  | 18 | 26 |
| 2 — передний правый (FR) | 17 | 25 |
| 3 — задний левый (RL)    | 16 | 33 |
| 4 — задний правый (RR)   |  4 | 32 |

- Скорость не регулируется: на мотор подаётся полный сигнал. Один вход `HIGH`,
  второй `LOW` — вращение; оба `LOW` — стоп. ШИМ не используется.
- Пины `ENA`/`ENB` на L298N должны быть постоянно включены (перемычки).
- Общая земля (GND) у ESP32 и драйверов обязательна.
- Если какое-то колесо крутится в обратную сторону, нужно поставить `-1`
  для него в массиве `MOTOR_SIGN`.

## Алгоритм

Задание состоит из шести этапов. Программа выполняет их строго по порядку.

1. **Старт.** Программа запускается сама при включении питания. Начинается
   подключение к Wi-Fi `ROBOT_ARM`, через 5 секунд (`BOOT_DELAY_MS`) стартует маршрут.
2. **Подъезд.** Робот едет по заданным участкам к манипулятору (см. маршрут ниже).
3. **Остановка.** Робот встаёт так, чтобы багажник был под манипулятором,
   и выключает все моторы. Перед запросом выдерживается пауза 700 мс
   (`SETTLE_MS`) и проверяется, что в сети тихо (`RX_QUIET_MS`).
4. **Запрос погрузки.** Робот отправляет манипулятору `LOAD` (UDP). Если
   `STARTED` или `BUSY` не пришли за 3 секунды, `LOAD` отправляется снова.
   Всего 4 отправки: первая и три повтора.
5. **Ожидание.** Робот стоит неподвижно и ждёт `DONE`, но не дольше 30 секунд
   от первого `LOAD`. Если `DONE` не пришёл, робот остаётся стоять до
   перезагрузки и никуда не едет.
6. **Доставка.** После `DONE` робот сам едет к финишу и останавливается.

Общий лимит одной попытки — 180 секунд (`ATTEMPT_LIMIT_MS`). После лимита или
любой ошибки (нет Wi-Fi, тайм-аут `DONE`, неверная конфигурация) моторы
выключаются, робот остаётся неподвижным до перезагрузки (`RESET`).

### Маршрут

Робот стартует передом влево по карте:

1. вперёд 1.78 м;
2. поворот влево на `MAIN_ANGLE_DEG`, вперёд 6.25 м по диагонали, поворот
   вправо обратно (корпус снова смотрит влево);
3. боком влево 0.35 м (на карте вниз) — багажник под манипулятором, остановка;
4. `LOAD`, ожидание `DONE`;
5. боком вправо 0.35 м обратно, поворот вправо на угол финишной диагонали;
6. вперёд по диагонали 2.91 м, поворот влево обратно, вперёд 0.35 м в зону финиша.

Угол финишной диагонали считается в программе: влево = 2.70 − 0.35 = 2.35 м,
вверх = √(2.91² − 2.35²), угол = `atan2(вверх, влево)`.

Положение определяется только по времени (энкодеров и гироскопа нет): время
каждого участка равно расстоянию, делённому на скорость, или углу, делённому
на угловую скорость.

### Обмен по UDP

| Параметр | Значение |
|---|---|
| Wi-Fi | `ROBOT_ARM`, пароль `12345678` |
| Манипулятор | `192.168.4.1`, порт `4210` |
| Порт робота | `4211` (ответы приходят на него) |
| Команда робота | `LOAD` |
| Ответы манипулятора | `STARTED` / `BUSY` — погрузка идёт, `DONE` — кубик в багажнике |

Состояния погрузки: `PREPARE_LOAD` → `WAIT_STARTED` → `WAIT_DONE`. Ответы
принимаются только от `192.168.4.1`. Пакеты, пришедшие до первого `LOAD`,
отбрасываются, чтобы случайно не принять старый ответ.

## Структура кода

- **Константы** (в начале файла): пины, `MOTOR_SIGN`, скорости, размеры
  маршрута, тайм-ауты, параметры сети.
- **Функции движения:** `writeMotor`, `stopAll`, `setWheels`, `setMotion`
  (вперёд, боком, повороты).
- **Маршрут:** `buildRoute` собирает массив шагов с проверкой констант
  и пинов; шаг `LOAD_CUBE` — это остановка и погрузка.
- **Сеть и погрузка:** `serviceNetwork`, `sendArm`, `beginLoad`, `loadFault`.
- **Основной цикл:** `serviceAuto` ведёт робота по шагам маршрута,
  `loop` вызывает все сервисы без блокирующих задержек.

## Режимы проверки

| Режим | Что делает |
|---|---|
| `MOTOR_TEST_ONLY = true` | Через 3 с по очереди подаёт `HIGH` на каждый из 8 пинов на 2 с (колёса вывесить!). Нужно, чтобы определить, какой пин какое колесо крутит. |
| `AUTO_START = false` | Ручные команды в мониторе порта (115200, Newline): `f`/`b` вперёд/назад, `l`/`r` боком, `q`/`e` поворот, `1..4`, `-1..-4` отдельный мотор, `go` маршрут, `load` погрузка, `p`/`s` `PING`/`STATUS`, `x` остановка до перезагрузки. Для калибровки. |

## Калибровка

Все скорости в начале файла — **начальные оценки** (0.20 м/с и 90°/с), а не
измерения. Перед стартом нужно измерить реальные значения на роботе и
подставить:

| Константа | Что измерить |
|---|---|
| `FORWARD_MPS_*` | скорость вперёд, м/с |
| `STRAFE_*_MPS_*` | скорость боком, м/с |
| `TURN_*_DPS_*` | скорость поворота, град/с |
| `MAIN_ANGLE_DEG` | угол основной диагонали (сейчас 45°, по карте не задан) |

Способ: в ручном режиме отправить команду импульсом 0.8 с, измерить путь или
угол и разделить на 0.8 с. Затем проверить на целых участках и с кубиком.

## Ограничения

- Без энкодеров и IMU точность маршрута зависит от калибровки и состояния
  покрытия и аккумулятора.
- Плавного разгона нет, моторы включаются на полную мощность.
- Повороты на месте требуют свободного места вокруг корпуса.
- Нельзя полностью исключить, что запоздавший старый `DONE` будет принят за
  новый: в протоколе нет идентификаторов.
